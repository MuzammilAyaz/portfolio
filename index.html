LSRW Language Lab

A CEFR-aligned assessment engine handling hundreds of student sessions daily. I built the adaptive autopilot, and fixed a generator that had started repeating itself by giving it a memory of its own output.

1. The Adaptive Autopilot

Averaging skill scores lets a strong reader hide a weak speaker. So reading, listening, writing and speaking each clear an independent threshold, and promotion waits on consistency across a rolling five-to-seven session window. Session length escalates on a separate loop, so students neither sprint past their level nor stall inside it.

2. “Negative RAG”

An LLM with no record of what it has already produced starts circling: different words, same ideas. Every output stays technically valid, which is why a basic uniqueness check never catches it. That is not a prompting problem, it is a missing memory layer.

So every accepted question is embedded and stored, and each new candidate is checked against the whole history. Anything at or above cosine 0.85 is rejected and pushed into LangGraph state as negative context for the next attempt. Three consecutive rejections trigger a density check, and a saturated topic gets abandoned outright.

3. IELTS Bundling

Practice arrives as 24-question IELTS bundles pinned to a single CEFR level: 12 reading, 10 listening, one writing task and one speaking cue card. An LCG-based distribution keeps delivery non-repeating without storing a per-student shuffle. Content generation and autopilot selection stay fully separate, so either can change without breaking the other.

4. Speech & Scoring

Listening audio comes from Azure AI Speech, with speech rate tiered by CEFR level. Spoken answers are transcribed by AssemblyAI. Scoring escalates only as far as it needs to: rule-based keys first, BERT similarity next, and LLM rubric grading for what is left.

NeoEval

Test-case pass or fail tells you whether code works, not whether the student understood the problem. That signal thinned noticeably once students started coding with AI, and manual review does not scale past a few hundred submissions. So I built a classifier that grades the shape of the attempt.

Persona Classification

Submissions sort into four auditable bands. The classifier returns a strict schema rather than prose, covering approach, execution and confidence, so any judgement can be inspected and argued with. Low-confidence cases route to a human instead of publishing quietly.

Evaluated with deepeval against a synthetic C++ dataset built with deliberate persona-subtype variation, to find where the band boundaries blur before real students did. Later extended to SQL and JDBC with repair-effort scoring.

Phase two moves upstream of the code entirely: typing dynamics become features for gradient-boosted models that separate original work from copied. Behaviour is considerably harder to fake than a final answer.

Personal Brain (Graph RAG)

Outside production systems, I have been building a personal knowledge base that retrieves over a graph rather than a flat vector index. Vector proximity finds passages that sound alike; a graph can answer why two things are connected.

Built on LangGraph workflows with Model Context Protocol servers, mapping relationships between concepts so retrieval can traverse them instead of ranking them.
